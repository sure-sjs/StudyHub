# StudyHub · 个人学习导航

一个把日常学习和生活中常用的网站集中到一处的个人导航工作台。纯静态、零依赖，直接打开 `index.html` 即可使用（推荐本地 HTTP 服务），也可以原样部署到 GitHub Pages。

> 当前版本：**V0.2.0**

## 功能

- **动态分类导航**：全部网站 + 自定义分类；分类可在设置页新增、重命名、换图标与配色、调整顺序；主页导航实时按新顺序渲染。
- **紧凑网格卡片**：宽屏 4 列、中等屏 3 列、平板 2 列、手机 1 列；卡片包含图标、名称、用途说明、标签与使用次数。
- **三种排序**：使用次数（默认，从高到低）、最近使用、名称（中文按拼音）。切换分类后沿用当前排序。
- **全局搜索**：顶栏搜索框按名称、网址、用途说明、标签实时过滤，中英文子串匹配、英文忽略大小写；与分类、收藏、最近访问、标签筛选取交集。
- **标签系统**：每个网站最多 5 个标签（每个最多 12 字），支持逗号 / 中文逗号 / 分号 / 中文分号分隔，自动去重；主页标签筛选默认收起，展开后可搜索标签、查看常用标签与全部标签，多选时按 AND 组合；设置页「标签管理」汇总所有标签及使用数量，支持全局重命名与删除。
- **网站图标**：三种来源——自动 favicon（仅尝试站点根路径 `/favicon.ico`，不使用第三方服务）、图片 URL、本地上传。优先级为上传图片 → 图片 URL → favicon → 内置图标；任意环节加载失败都自动回退，不影响卡片。上传图片限制 2MB，自动压缩到不超过 128×128，优先 WebP、必要时 PNG，保存在 IndexedDB，不写入主数据。
- **主题**：浅色 / 深色 / 跟随系统；选择即时生效并保存在本地，跟随系统时会随系统深浅色自动切换。
- **数据管理**：导出完整 JSON 备份（含全部网站、分类、设置与上传图片的 Base64）；校验备份后整体恢复；恢复前自动导出一份当前数据，可用于回滚。
- **真实跳转**：点击卡片在新标签页打开对应网站。
- **访问统计**：打开网站后自动 +1 次使用次数，并记录最近使用时间；「最近访问」按时间倒序展示最近 5 条。
- **收藏**：卡片右上角星标可收藏 / 取消收藏，「我的收藏」查看收藏列表，空状态有提示。
- **网站管理**：标题区「添加网站」打开表单弹窗，必填名称、网址、所属分类，可选用途说明与标签；卡片右上角「⋯」菜单提供编辑与删除，删除前二次确认。
- **本地持久化**：网站、分类、设置保存在 `localStorage`，上传图片保存在 IndexedDB；刷新后原样恢复。
- **只读保护**：检测到存储损坏、迁移失败或存储被禁用时进入只读模式，顶部显示横幅，禁止写入但保留浏览、搜索、筛选与打开网站。
- **响应式与无障碍**：无横向溢出，键盘可遍历导航、排序与卡片，焦点样式清晰，弹窗支持 `Esc` 关闭，支持 `prefers-reduced-motion`。

## 目录结构

```
StudyHub/
├─ index.html            # 页面骨架、内联 SVG 图标 sprite、主题初始化脚本、各类 dialog

├─ js/
│  ├─ data.js            # 分类与初始网站数据（仅首次访问的种子）
│  ├─ store.js           # V3 数据层：校验、读写、迁移状态机、只读保护
│  ├─ icons.js           # IndexedDB 图标存储（上传图片）
│  └─ app.js             # 状态管理、渲染、搜索筛选、分类/标签管理、主题、备份恢复
├─ assets/
│  └─ icons/
│     └─ favicon.svg     # 站点图标
├─ .nojekyll             # 关闭 GitHub Pages 的 Jekyll 处理
└─ README.md
```

## 本地预览

直接双击 `index.html` 也能打开；若浏览器对本地文件有限制，用任意静态服务器：

```bash
# 任选一种
npx serve .
python -m http.server 8123
```

然后访问终端里给出的地址（例如 `http://localhost:8123/`）。

## 部署到 GitHub Pages

1. 新建仓库并推送本目录内容到 `main` 分支：

   ```bash
   git init
   git add .
   git commit -m "StudyHub V0.2.0"
   git branch -M main
   git remote add origin https://github.com/<用户名>/<仓库名>.git
   git push -u origin main
   ```

2. 仓库 **Settings → Pages**：Source 选择 `Deploy from a branch`，Branch 选 `main` + `/ (root)`，保存。
3. 等待 1–2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

所有资源都使用相对路径，仓库名随意，无需额外配置。数据只存在各自浏览器里，部署后新增的网站不会自动出现在其他设备上。

## 数据结构

### 种子数据 `js/data.js`

`data.js` 通过全局变量 `window.STUDYHUB_DATA` 暴露初始数据（普通 `<script>` 加载，不使用 ES modules / fetch）：

```js
{
  meta: { version: '0.2.0' },
  categories: [{ id, name, icon, color }],
  sites: [{
    id, name, desc, url, category,
    icon, color, tags: [],
    initialVisits,       // 首次使用时的初始次数
    seededHoursAgo       // 首次使用时的初始「最近访问」时间
  }]
}
```

它只作为**首次访问的种子**。一旦浏览器里已有 V3 数据，再修改 `data.js` 不会影响现有内容；需要重置时清除该站点的 `localStorage` 与 IndexedDB 后刷新即可重新播种（建议先导出备份）。

### 运行时存储（V3）

- `localStorage["studyhub:data"]`：主数据（网站、分类、设置）。
- `localStorage["studyhub:meta"]`：迁移/健康状态（正常或只读原因）。
- `localStorage["studyhub:backup:v2-<时间戳>"]`：V2→V3 迁移时自动生成的原始数据备份，不会被自动删除。
- `localStorage["studyhub:v1"]`：V0.1/V0.2 早期的旧键，仅在迁移时读取，不会自动删除。
- `IndexedDB["studyhub-icons"]` / store `icons`：上传图片的 Blob 与元信息，按 `imageId` 引用。

主数据结构：

```js
{
  schemaVersion: 3,
  appVersion: '0.2.0',
  updatedAt: <时间戳>,
  settings: { theme: 'system', sort: 'visits', searchScope: 'all' },
  categories: [{ id, name, icon, color, order, builtin }],
  sites: [{
    id, name, desc, url, category, tags: [],
    icon: { source: 'builtin' | 'auto' | 'url' | 'upload', symbol, url, imageId },
    color, order, visits, lastUsed, favorite, createdAt, updatedAt
  }]
}
```

`icon.imageId` 只是 IndexedDB 中的记录键，Base64 永远不会写入主数据。

### 旧数据迁移

- 首次加载 V3 时，如果存在 `studyhub:v1`（V0.1/V2 的「基础数据 + 记录分离」结构），会自动迁移为 V3：合并次数、收藏与最近使用，补齐分类顺序、网站顺序与时间戳。
- 迁移前先写备份并回读校验，备份失败会中止迁移；中途失败会进入只读模式并给出提示，不会静默覆盖数据。
- 迁移失败会进入只读模式，并在横幅中说明原因；修复浏览器存储可访问性后刷新即可重试。旧键与备份键始终保留，不自动清理。

## 数据备份与恢复

1. 打开右上角设置 → **数据管理**。
2. 点击 **导出完整备份**，会下载形如 `StudyHub-20261104-2115.json` 的文件。
3. 备份包含：全部网站（含图标配置）、分类、设置，以及 **IndexedDB 中所有上传图片的 Base64 数据**，可以在另一台电脑或另一浏览器中完整还原。
4. 恢复时点击 **选择备份文件**，校验通过后会显示备份时间、网站/分类/图片数量；确认后会用备份内容**整体替换**当前数据。
5. 恢复开始前会自动下载一份当前数据的 `StudyHub-before-restore-*.json`；如果恢复失败，当前数据会保持原样，这份文件可作为额外的手动回滚手段。
6. 恢复完成后页面自动刷新。

注意：

- 备份文件包含上传图片，体积可能较大；当前单次导入上限为 40MB。
- 恢复是整体替换，不是合并。
- 备份包含 IndexedDB 中未被引用的历史图片；恢复成功后会清理恢复前的旧图片，通常不会产生重复记录。
- 只读模式下，只要主数据仍可读取就允许导出；导入与恢复一律禁用。

## 校验规则

| 字段 | 规则 |
| --- | --- |
| 网站名称 | 必填，最多 30 字 |
| 网站网址 | 必填，自动补全 `https://`；仅允许 http / https；域名需含点；去掉 `#` 片段后保存 |
| 重复网址 | 忽略 `www.`、末尾 `/` 与大小写差异后判重，重复时拒绝保存 |
| 所属分类 | 必选，必须是现有分类 |
| 用途说明 | 可选，最多 60 字 |
| 标签 | 可选，最多 5 个，每个最多 12 字；按 `,` `，` `;` `；` 分隔，空格保留在标签内部，自动去重与忽略空项 |
| 分类名称 | 必填，最多 20 字，同一分类不可重名 |
| 分类删除 | 分类下有网站时必须先选择迁移目标；至少保留一个分类 |
| 图标 URL | 必填，仅 http / https，加载失败自动回退 |
| 上传图片 | PNG / JPEG / WebP，单张 ≤ 2MB，压缩后 ≤ 128×128 |
| 备份文件 | 必须是 `studyhub-backup` 格式、`schemaVersion: 3`，图片 Base64 与引用关系必须完整 |

## 技术说明

- 原生 HTML / CSS / JavaScript，无框架、无第三方依赖、无外部字体与 CDN 请求。
- 普通 `<script>` 顺序加载：`data.js` → `store.js` → `icons.js` → `app.js`。
- 图标为内联 SVG `<symbol>` + `<use>`；自定义图片以 `<img>` 叠加，遵循主题但不对图片本身做反色。
- 主题通过 `html[data-theme]` 与 CSS 变量实现；`<head>` 内联脚本在首帧前恢复主题，避免闪白。
- 表单使用原生 `<dialog>`，自带焦点管理与 `Esc` 关闭；关闭时同步解除页面滚动锁。
- 数据渲染对文本做 HTML 转义、对 URL 做协议校验，避免引入不可信内容；用户输入永远不会作为 HTML 注入。
- 所有写入都经过 `SH.store` 校验与候选文档提交，失败时内存状态不变。
